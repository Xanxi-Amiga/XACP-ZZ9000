# ZZStrider 1.0 - Core1 blob sources

Source of `zzstrider.bin`, the bare-metal program that emulates the Capcom CPS-1 arcade board of
*Strider* (1989) on the second Cortex-A9 core (Core1) of the MNT ZZ9000.
Requires firmware XX19d-RIX or later XACP-compatible firmware.

This archive is the source of the blob only. The AmigaOS launcher (`ZZStrider`) and the front end
(`ZZStriderGUI`) are separate proprietary closed-source freeware programs distributed as binaries; they contain none of the
code below and only exchange data with the blob through the shared-memory protocol defined in
`arm/zzs_shared.h`. **No ROM is included.**

## Build

    sh build_all.sh

Offline, PATH unchanged. The compilers are called through the explicit paths at the top of
`tools/build.py` (Windows Arm GNU Toolchain 13.2 Rel1 by default); each path can be overridden
with an environment variable of the same name (`ZZS_ARM_GCC`, `ZZS_ARM_GXX`, `ZZS_ARM_OBJCOPY`).
Result: `out/zzstrider.bin` and `out/CHECKSUMS.txt` (size, MD5, SHA-256). Other toolchains may produce a different binary due to differences in compiler, newlib and libgcc versions.

`tests/run_host_test.sh` is an optional regression test on a Linux host (qemu-arm user mode) with a
synthetic ROM set generated by `tests/make_synth_roms.py`; it involves no Capcom data.

## What is in the blob

| Part | Where | Origin |
|---|---|---|
| Platform: entry, vectors, MMU map, PMU, memset/memcpy, heap | `arm/zzs_entry.S`, `zzs_vectors.S`, `zzs_mmu.c`, `zzs_platform.c` | written for the ZZ9000 (after ZZRastan 1.0) |
| Mailbox, pacer locked on the display, pause, stop | `arm/zzs_main.c` | idem |
| ROM loading by 64 KiB chunks, CRC32 check, decoding | `arm/zzs_rom.c`, `zzs_cps_load.cpp` | ZZStrider transport and CRC bookkeeping; incremental decoding and graphics mask computation derived from FB Alpha 2012 |

| PCM ring read by AHI, sound rate control | `arm/zzs_audio.c`, `zzs_sound.c` | idem |
| CPS-1 video and input engine | `arm/cps1/` behind `arm/burn_shim/`, `zzs_burn.cpp`, `zzs_cps_run.cpp` | FB Alpha 2012 (libretro/fbalpha2012_cps1), corrections from FBNeo and MAME, see `arm/cps1/README.md` |
| 68000 | `third_party/cyclone/` (generated core included) | Cyclone 68000 (FinalDave and notaz), MAME-licence option |
| Z80 | `third_party/cz80/` | CZ80 (Stephane Dallongeville), as in PicoDrive |
| YM2151 | `third_party/ym2151/`, `arm/zzs_ym_jarek.c` | Jarek Burczynski |
| MSM6295 | `arm/zzs_msm6295.c` | written after MAME `okim6295.cpp` (BSD-3-Clause) |

Only `arm/zzs_game.h` and the ROM table of `arm/zzs_rom.c` name the game; the CPS-B and mapper
tables of the other CPS-1 games are still in `arm/cps1/cps_config.cpp`.

## Memory plan (ARM addresses)

The 68k sees the ZZ9000 frame buffer at `fb = board + 0x10000`; ARM address =
`0x00200000 + (68k address - fb)`. All constants live in `arm/zzs_shared.h`.

| Area | ARM | Size | Cache | Use |
|---|---|---|---|---|
| Blob | `0x04500000` | up to `0x1F0000` | WB/WA | code and data |
| Shared slots | `0x04700000` | 248 words, below `0xFE0` | non-cached | mailbox, diagnostics |
| ROM staging | `0x04B00000` | 64 KiB | non-cached | one window reused for every chunk |
| PCM ring | `0x05700000` | 512 KiB | non-cached | S16 mono 22050 Hz, read by AHI |
| BSS and private stack | `0x22000000` | 4 MiB reserved | WB/WA | stack 256 KiB |
| Decoded ROM store | `0x22400000` | 8 MiB reserved | WB/WA | graphics, 68000 program, Z80, samples |
| newlib heap | `0x22C00000` | 1 MiB | WB/WA | |
| CPS-1 arena | `0x22D00000` | 3 MiB | WB/WA | 68000 RAM, video RAM, engine tables |
| Picasso96 buffers | published by the launcher | 3 buffers | WB/WA on demand | conversion targets |

Everything else is Strongly-Ordered (peripherals as Device). Avoided: the XACP rings
(`0x042xxxxx`-`0x044xxxxx`), the firmware marker at `0x04700FE0`, the ZZMIDI corridor and pool,
the reserved graphics framebuffer window and the Core0 heap.

When the blob maps a Picasso96 buffer write-back, the new descriptor is cleaned through the PL310
L2 cache before the TLB is flushed: the table walk does not snoop L1, and without this the buffer
can stay Strongly-Ordered (conversion up to five times slower). The resulting attributes are read
back with `ATS1CPR` and reported in the shared slots.

Loading protocol: `INIT` -> `ROM_BEGIN` -> for each file in the order of `ZZS_ROM_LIST`, sequential
`ROM_CHUNK` commands of 64 KiB at most -> `ROM_COMMIT` (all 16 CRC32 correct) -> `START`. Any
problem leaves the mailbox alive with `ERROR` and `ERROR_AUX` set.
